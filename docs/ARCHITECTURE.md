# tetron architecture & module map

> Referenced from `AGENTS.md`. Load-bearing constraints (protected identifiers, spec workflow) live there, not here — read this file for the addressing scheme, daemon architecture, module map, and key flows.

P2P mesh VPN powered by [iroh](https://iroh.computer). Connects peers by cryptographic identity (EndpointId), not IP address. Dual-stack addressing: stable IPv4 in a **configurable** overlay subnet (default `10.88.0.0/24`; FNV-1a of identity, host-bit width follows the prefix) and stable IPv6 in `200::/7`, **per-network since IPV6-001** (blake3 of `identity:network` for the low 72 bits, blake3 of `network` alone for a 48-bit network-prefix — every member of one network shares the same routable `/56`, and the same identity gets an unrelated address in each network it joins; never rotates).

## Architecture

```
App → TUN (10.88.x.x / 200::x) → tetron → iroh QUIC datagrams → peer
```

One shared iroh `Endpoint` spans every network, but **each joined network gets its own TUN device and subnet (MULTISEG-002..007)** — like plugging two physical NICs into two different networks. Unlike physical NICs, though, traffic never crosses between a node's own segments: `forward.rs` looks up a packet's destination only in the network it arrived on, so cross-network routing would need new gateway/relay code that doesn't exist (out of scope). The practical bridge is jump-hosting at the application layer (`ssh -J`, port forwards, a SOCKS proxy), since a multi-homed node already has its own native connection to each network it belongs to. Each network gets its own ALPN (`tetron/net/<version>/<pubkey-prefix>`); `ProtocolRouter` dispatches by ALPN. The `<version>` segment (`transport::MESH_PROTOCOL_VERSION`) is the **mesh protocol-version gate** — peers on different versions share no ALPN and can't connect; bumping it on a breaking change severs old peers automatically.

> **Multi-segment TUN (MULTISEG-002..007).** `NetworkHandle` (not `MeshManager`) owns the data-plane bundle per network: its own `PeerTable`, TUN device name, TUN write channel, forwarding tasks. `MeshManager::create_and_attach_network_tun` creates each network's TUN in its own subnet (`NetworkConfig.subnet`, always explicitly persisted, SUBNET-DRIFT-001); `activate()`/`deactivate()` iterate every network's TUN independently; teardown calls `tun::delete()` to actually remove the device. IPv6 is also network-scoped now (`derive_ipv6(identity, network)`, IPV6-001..003) — every joined network gets its own disjoint, routable `/56`, reachable simultaneously. **Known limitation:** a node in two networks still does not route traffic between them (see above); jump-hosting is the workaround, transparent cross-network routing is out of scope. See `MULTISEG-003`/`MULTISEG-007` and `IPV6-001..003` in `spec/` for detail. A restored network validates its subnet against the identity's own signed roster IP before attaching a TUN, refusing rather than silently drifting.

### Modules

- `src/main.rs` — thin clap CLI + IPC client (`Cli`/`Command`, tracing/panic plumbing). `tetron daemon` (hidden) runs the daemon loop; `build.rs` stamps the git SHA shown by `tetron version`. Command handlers live in `src/cli/`, one file per domain (`network`, `status`, `invite`, `admin`, `service`), each `pub(crate)`, flattened via `src/cli/mod.rs`.
- `src/daemon/` — daemon process, directory module. Core type **`MeshManager`**: holds the endpoint, networks map, blob store, `ProtocolRouter`. The TUN device and `PeerTable` are per-network, living on each **`NetworkHandle`** (MULTISEG-002/003). `mod.rs` holds the core types (`MeshManager`/`NetworkState`/`NetworkHandle`/`MeshCtx`) and the IPC dispatcher (`handle_request`, `check_authorized`, `set_operator`, `mesh_ctx_for`). The bulk lives in `src/daemon/mesh/`, re-exported so callers reach functions by bare name:
  - `accept.rs` — `CoordinatorAcceptState`/`MemberAcceptState`/`ProtocolRouter`
  - `join.rs` — `join_mesh_shared`, `spawn_reconnect_loop`
  - `bootstrap.rs` — `run_daemon`, `build_daemon`, `serve_ipc`
  - `publish.rs` — DHT publishers (`update_snapshot_and_publish`)
  - `reconverge.rs` — blob refetch/apply, the group poller (`tetron config set poller-interval`, default 60s; wakeable early via `tetron sync`, SYNC-001)
  - `coordinator.rs` — coordinator control reader, peer cleanup, used by `kick`
  - `select.rs` — pure decision helpers (`coordinator_dial_order`, `choose_path_index`, …)
  - `create_join.rs` — `join_network_inner` (resolve blob → dial → finalize)
  - `invite_handler.rs` / `admin.rs` / `runtime.rs` / `diagnostics.rs` — per-domain IPC ops as `impl MeshManager` methods

  **`MeshCtx`** bundles the cheap-`Clone` handles (identity, `PeerTable`, `tun_tx`, stats, blob store, pruned-peers) a network's accept states/background tasks need, built per network via `new_network_data_plane()` or looked up via `mesh_ctx_for(network)`. Admission (invite-only, LIVE-001): `CoordinatorAcceptState::handle_connection` → `redeem_invite_and_admit` → `admit_peer` — no invite, no admission. Every publish, including a coordinator's first one after restart, reads the real DHT state before writing (`dht_read_before_write`, CONVERGE-008) so a stale local restore can't clobber a live blob.
- `src/ipc.rs` — thin shim; the `IpcMessage` enum, `MsgpackCodec` (length-prefixed msgpack over Unix socket), and socket helpers live in `tetron-proto`. Socket at `/var/run/tetron/tetron.sock`.
- `src/identity.rs` — persistent Ed25519 keypair (`<config_dir>/secret_key`, `0600`); device certs. Resolves its dir via `config::config_dir()`.
- `src/invite.rs` — invite-code encoding/decoding: `bs58(network_pubkey(32) || secret(16))` (48 bytes, BLOB-001). No pinned coordinator — invite entries ride the signed `GroupBlob`, so any network-key holder validates. Reusable keys and single-use invites both live in the blob (`membership::ReusableKey` / `InviteEntry`).
- `src/membership.rs` — `IdentityProvider`, IPv4/IPv6 derivation, `MemberList`/`ApprovedList`, `GroupBlob { members, approved, name, reusable_keys, invites, nuke_proposals }` with canonical msgpack + blake3 hashing. **Subnet is configurable:** `default_subnet()` returns `10.88.0.0/24`; the authoritative subnet rides the `GroupBlob`/config, and IP derivation is subnet-relative. `assign_ip` picks the lowest free collision index at admission. `NUKE_PROPOSAL_TTL_SECS` (default 24h) is overridable (`tetron config set nuke-proposal-ttl <duration>`, CONFIG-AUDIT-002).
- `src/transport.rs` — iroh endpoint setup, per-network ALPN (`tetron/net/<MESH_PROTOCOL_VERSION>/<prefix>`); optional Tor transport (`tor` feature). The shared endpoint binds a **fixed UDP port** (`TETRON_LISTEN_PORT`, 43737 compiled default, overridable via `tetron config set listen-port <port>`, CONFIG-AUDIT-002 — daemon-wide since one `Endpoint` serves every network), stable across restarts and manually port-forwardable; falls back to an ephemeral port if in use. **Relay/discovery overrides** (`tetron config set relay|discovery-dns ...`) conditionally swap `config::ServerOverride` into `bind_endpoint`; no-ops when unset.
- `src/tun.rs` — async dual-stack TUN (IPv4 + IPv6 /128), split into `TunReader`/`TunWriter`. Every function (`create`, `set_link_up`/`down`, `route_peer_range`, `delete`) is parameterized by device name, called once per network (MULTISEG-002/003). `route_peer_range` (IPV6-003) installs a network's own `/56` peer-range route after link-up. `delete(tun_name)` (MULTISEG-003) actually removes a network's device on teardown instead of relying on the kernel at process exit. Idempotent across `up`/`down`.
- `src/selfcapture.rs` — self-capture routing mitigation (SELFCAPTURE-ROUTE-001, closing `TUN-CAPTURE-001`): every tetron node's TUN device installs an OS subnet route (e.g. `10.88.0.0/24 -> tun0`) that iroh doesn't know is virtual, so it can offer a peer's own overlay IP as a dial candidate that gets swallowed locally instead of reaching the real remote host. Fix: route iroh's own outbound traffic (identified by its fixed source port) around every overlay subnet route — an `ip rule`/shadow-table on Linux, a `pf` sub-anchor on macOS. Applied once, daemon-wide, at `build_daemon`; idempotent and fail-open. Configurable (`tetron config set selfcapture-mitigation off`); torn down only at `tetron uninstall`.
- `src/forward.rs` — TUN ↔ peer forwarding via dual-stack routing lookup; labeled drop counters. Inbound datagrams pass only the upstream ingress anti-spoof check; packet *filtering* is the host firewall's job (MINIMAL-010). **Oversized-packet fragmentation (FRAG-001/FRAG-002):** when a TUN packet exceeds Quinn's path-MTU-discovery ceiling, `run_mesh` fragments it before sending — real RFC 791 fragments for IPv4, a tetron-internal envelope + per-connection `packet::Ipv6Reassembler` for IPv6 (RFC 8200 has no in-header IPv6 fragmentation).
- `src/packet.rs` — minimal IP-header parser (`PacketInfo`/`parse_packet_info`) for the data path: peer routing, the anti-spoof check, and the fragmentation helpers (`fragment_ipv4`/`fragment_ipv6`/`Ipv6Reassembler`) used by `forward.rs`.
- `src/dht.rs` — one pkarr record per network (blob hash + seed peers + `m,<mesh-version>`); only the coordinator (per-network secret key) can publish. Relay URL defaults to `dns.iroh.link/pkarr`, follows `discovery-dns` config when set.
- `src/control.rs` — length-prefixed msgpack control protocol over QUIC streams (`JoinRequest`, Welcome, MemberApproved, MeshHello, BlobUpdated, `AdminGrant`, `InviteShare`, `InviteUsed`, `Ping`/`Pong`, …). **D1 wire compat:** `DeviceCert`/`PairMsg`/`CertRefresh`/`Unpaired` types are retained but inert — decoded and ignored, never errored, always sent as `None`. All triggers pass through the `ControlGate` rate limit.
- `src/peers.rs` — `PeerTable` (dual v4/v6 DashMaps). A peer keeps one virtual IP across every network it joins; `PeerEntry` holds a *set* of connections. `remove_peer_from_network()` drops one network's route, `remove()` drops it everywhere.
- `src/peercache.rs` — on-disk peer address cache (CACHE-001): persists each peer's last-known `TransportAddr`s (relay URL + direct IPs) to `<config_dir>/peercache.msgpack` on graceful shutdown and every 5 minutes. `connect_to_peer_with_alpn` tries cached addresses before falling back to DHT lookup, so reconnection works through an all-offline gap. Entries older than 30 days are pruned on load; stale addresses are harmless since iroh's QUIC handshake verifies identity regardless of dialed address.
- `src/config.rs` — config storage. **Sharded, atomic, per-network:** globals in `settings.toml` (`operator_uid`, `default_hostname`, `ServerOverride` settings, subnet, plus `nuke_proposal_ttl`/`listen_port`/`poller_interval`/`log_retention`/`invite_default_expiry`, CONFIG-AUDIT-002); each network in `networks/<name>.toml`. Writes go through `write_file` (temp + atomic `rename`). **Location:** `config_dir()` is `/etc/tetron` on Linux, `~/.config/tetron` on macOS; secret-bearing files `0600 root:root`, non-secret `0640 root:tetron`. **Overridable (PORTABILITY-003):** `TETRON_CONFIG_DIR`/`TETRON_LOG_DIR`/`TETRON_SOCKET_PATH` relocate the config dir, log dir, and IPC socket respectively — motivated by NixOS's non-FHS layout. **The relay preset keyword `"rayfish"` is retained (CON-001) — do not rename.**
- `src/hostname.rs` / `src/network_name.rs` — hostname + local-alias generation and collision resolution (`resolve_collision` appends `-1`, `-2`, …).
- `src/stats.rs` — iroh-metrics `ForwardMetrics` counters for the forwarding data path (rx/tx/drop reasons) + periodic stats logger, surfaced via `tetron status`/`--json`.
- **CLI presentation**: plain text output (no colors, spinners, or glyphs). `--json` on every read command provides machine-readable output.
- `src/logdir.rs` — daemon log directory (`/var/log/tetron` on Linux, `/Library/Logs/tetron` on macOS). Rolling daily files via `tracing-appender` (7 most recent retained).
- `src/ratelimit.rs` — `ControlGate`: per-connection token-bucket guard + strike counter over inbound control messages (`check()` returns `Verdict::Allow`/`Drop`/`Close`). **`GlobalRateLimiter`** (HARDEN-004) is a single daemon-wide instance, cloned via `Arc` into every network's `MeshCtx`, consulted alongside the per-connection gate — both must Allow. Both the per-connection defaults (`CAPACITY=5`/`REFILL_PER_SEC=1`/`STRIKE_LIMIT=20`) and the global ones (`GLOBAL_CAPACITY=10`/`GLOBAL_REFILL_PER_SEC=3`/`GLOBAL_STRIKE_LIMIT=50`) are configurable overrides (HARDEN-005).
- `src/shutdown.rs` — SIGINT/SIGTERM via `CancellationToken`.

### Key flows

- **Create:** generate per-network `SecretKey` → derive addresses from the subnet (default `10.88.0.0/24`, or `--subnet`) → build initial `GroupBlob` → publish blob + signed pkarr record → persist keys/`group_mode`/subnet → print the public key as room id. Always closed (`Restricted`, MINIMAL-013 removed `--open`). **Subnet-collision guards:** an explicit `--subnet` overlapping another of this node's own networks is refused unless `--force` (SUBNET-COLLISION-001); an unspecified `--subnet` auto-advances past conflicts. The resolved subnet is also checked against the host's real interfaces at `create`/`join` time (SUBNET-COLLISION-002), fail-open if the enumeration tool is missing.
- **Access modes & admission:** the room id (network public key) is a discovery key only, never an admission credential. tetron is **invite-only** (LIVE-001): a bare room-id join is always denied. The joiner presents an invite secret to any online coordinator, validated against the signed `GroupBlob` via `redeem_invite_and_admit`. A coordinator also honors a **reusable key** from `GroupBlob.reusable_keys` (D1 compat). Handled by `CoordinatorAcceptState`, run by any node holding the network key; the coordinator assigns the joiner's IPv4 via `assign_ip`.
- **Join handshake:** resolve pkarr record → fetch/verify `GroupBlob` → dial coordinators in `coordinator_dial_order` until one replies `Welcome` → send `JoinRequest{invite_secret}` → coordinator validates and replies `Welcome`/`JoinDenied`. No invite secret means always denied. Then `MeshHello` to other members and poll pkarr for blob updates.
- **Gatekeeper:** any coordinator (any network-key holder) can admit a joiner and broadcast `MemberApproved` — admission survives any single coordinator being offline. Members reconnect without any coordinator online at all.
- **DHT (single-record):** one pkarr record per network, signed by the per-network secret key (the pkarr address *is* the network public key — unspoofable). `spawn_group_poller()` refetches on hash change every 60s (configurable, `poller-interval`).
- **Reachability model (segmentation-first):** a network is the reachability boundary — two peers exchange packets iff they share ≥1 network. No per-device packet filter (MINIMAL-010); restrict ports with the host firewall on the TUN interface. The only in-daemon ingress check is anti-spoofing (a peer may only source packets from its own mesh IP).
- **Multiple admins = shared network key.** `tetron admin <net> add <id>` grants the key to a member over the authenticated mesh ALPN (`AdminGrant`), making it a co-coordinator (`promote_to_coordinator`).
- **Hostname (fixed at join):** rename propagation was removed (MINIMAL-014). A member's hostname is set once at join; the coordinator resolves collisions at admission (`resolve_collision`, suffix `-1`, `-2`, …), and a member adopts the authoritative name from the signed roster on reconverge (`reconcile_local_hostname`).
- **Reconnection:** per-peer reader detects drop → coordinator removes the dead peer; joiner reconnects with exponential backoff (1s–30s) then re-sends `MeshHello`.
- **Control-plane abuse defense:** both control read loops gate each connection with a per-task token bucket (`ControlGate`) *and* the shared daemon-wide `GlobalRateLimiter` (HARDEN-004) — both must Allow. A sustained flood trips `Verdict::Close` (`forward::ABUSE_CODE`). `MemberSync`/`BlobUpdated` only wake a per-network debounced reconverge worker (~300ms coalesce, single-in-flight).
- **Leave:** `tetron leave` closes connections with `forward::LEAVE_CODE` (an intentional disconnect, unlike a plain timeout/reset); the coordinator prunes the member and republishes. **Sole-coordinator auto-promotion (STRANDED-COORDINATOR-WARN):** if the caller is the network's only coordinator and other members exist, `leave_network` first grants the key to every currently-connected member; refuses only if someone remains unreachable (unless `--force`).
- **Kick:** `tetron kick <network-key> <endpoint-id>` is coordinator-authoritative; both args resolve by cryptographic short id, never a local name. Removes the roster + approved entry, republishes, closes links with `KICK_CODE`. `prune_departed_peers` closes/unroutes any live connection no longer in the applied roster. **Any coordinator may kick any other, unilaterally, no consensus** (KICK-COORDINATOR-001) — mainly for a coordinator whose machine is permanently gone (its stale entry otherwise defeats `leave`'s stranding check and `nuke`'s consensus gate). **Not key revocation:** a kicked coordinator still holds the shared `network_secret_key` and could self-mint an invite and rejoin — real key rotation isn't built (see `DO-NOT-COMMIT/TODO.md`'s "Coordinator key security" section).
- **Nuke requires consensus on 2+ coordinators (NUKE-CONSENSUS), threshold configurable at create (NUKE-CONSENSUS-THRESHOLD-001):** on a solo-coordinator network, `tetron nuke <network-key>` destroys immediately (empty tombstone record + `leave_network`). With 2+ coordinators, it adds the caller to `GroupBlob.nuke_proposals` and republishes; once distinct unexpired proposers (24h TTL) reach the network's configured threshold (default 2, `--nuke-consensus <n>` at create) it executes synchronously within that same command. `--cancel` withdraws the caller's proposal; `--second <short-id>` seconds an existing one. Deliberately no reconverge/poller-triggered automatic execution — only the synchronous command handler ever publishes the tombstone, so a node that merely observes consensus in a fetched blob never acts on it alone.
- **Network/peer identifier resolution (CLI-VOCAB-002):** `leave`/`invite`/`admin` resolve by local display name first, falling back to a `network_key` prefix (10-char minimum) — none of these three mutate anyone else's roster, so unlike `nuke`/`kick` there's no destructive-action reason to require the key. `nuke`/`kick` resolve by cryptographic short id only, no name/alias fallback — a network's identity is its key, not its local label. Peer args: `admin add` resolves hostname-first then short-id; `kick`'s target and `nuke --second` resolve by short id only, since a destructive action needs a cryptographic identity, not a spoofable one.
- **resume/standby (data plane) vs start/stop (whole daemon) — renamed from up/down (CLI-VOCAB-004):** the daemon connects every saved network at startup and keeps those connections for its lifetime; `activate()`/`deactivate()` toggle only the **data plane** (TUN link, routes, forward gate). `tetron standby` stays connected to peers with no traffic; `tetron resume` is near-instant and errors cleanly (never silently installs) if the daemon isn't reachable. **Per-network (STANDBY-PER-NETWORK):** `--network <name>` scopes to one joined network instead of every one, via each `NetworkHandle`'s own `active` flag.
- **`tetron status` output (STATUS-002):** per-network block is `network <name> subnet <cidr> admins <online>/<total> members <online>/<total> interface <tun_name>`, then `network_key` (admins only), then a column-aligned `role/host/ip/via` table with the local node first (`via (you)`). `role` is `admin`/`member`; `via` is `direct`/`relay`/`tor`/`offline`/`(you)`. `--json` adds per-peer IPv6, rtt/tx/rx, `drops`/`fragmented_ipv4`/`fragmented_ipv6` counts, the full per-candidate `paths[]` list (`PATH-DIAG-002`), and `via_detail` explaining why `conn_type` isn't `Direct` (`PATH-DIAG-004`). **Path-bleed hardening (PATHBLEED-STATUS-001/002/003):** iroh shares path-selection state across a peer's networks, so a path belonging to a *different* one of that peer's networks could otherwise show as selected here too. `gather_conn_info` only trusts a candidate whose address falls inside **none** of this daemon's own managed overlay subnets — checked against every joined network, not just the one being queried (`PATHBLEED-STATUS-003`; an earlier cut that checked only the current network's own subnet rejected genuine candidates almost universally) — and shows real *received* traffic (`udp_rx`, not merely attempted `udp_tx`), tiered above plain classification. Two narrow residual gaps are documented, not fixed, in `PATHBLEED-STATUS-003`'s own spec docstring.
- **Tor (optional):** `--tor` adds `TorCustomTransport` alongside relay; onion address derived from the iroh `SecretKey`. Needs a Tor daemon (`ControlPort 9051`).
